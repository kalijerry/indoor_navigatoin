# 办公室精度测试流程

在一间约 200 m² 的办公室里，用同一套步骤反复测地磁定位的精度，改完算法再测，对比数字有没有变好。
蓝牙在这里关掉，成绩只反映「地磁 + ARKit」。

## 流程总览

扫房间 → 采集建图会话 → 上传 → 云端融合 → 下载融合后的地图 → 走测试会话 → 上传 → 再融合 → 看成绩。

App 里「地磁定位 → 地图」页的「精度测试」入口把这些步骤列成清单，显示每一步做到哪了，也能看成绩和趋势。

## 步骤

### 1. 扫房间

「房间扫描」页：填名字，拿着手机沿墙慢慢绕一圈，把墙、门、大家具都扫到，点「扫完了」。扫完自动加进地图库并切换过去。
200 m² 比较大，分两三圈扫，别走太快；扫完看 2D 平面图，墙明显缺了就重扫。
（办公室里隔断、工位很多时，RoomPlan 可能漏掉一部分，可走区域会偏大，这不影响测试，只影响「覆盖率」的数字。）

### 2. 采集建图会话（至少 3 段）

「地磁定位 → 采集」：开始建图采集 → 在地图上长按一个你能准确指出的点定起点 → 设朝向 → 沿朝向直走 1.5 m → 把地面走满。

- 手机竖着拿，摄像头朝前下方，不要带磁吸壳，每段 5～10 分钟。
- 每段走法不要完全一样：一段沿长边来回扫，一段沿短边，一段沿墙绕圈。目标是让地图上的绿色涂色覆盖所有走得到的地方，每个地方最好从两个方向各走过。
- 途中不用长按修正（房间里没有通道可贴，修正可选）。ARKit 跟踪变成「受限」时停一下，让它恢复。
- 结束采集后会话自动上传到云端后台（「门店数据 → 云端后台」里要先填地址、口令并打开连接）。

### 3. 触发云端融合

GitHub 仓库 → Actions → **Cloud map build** → Run workflow：

- `map_id`：留空处理全部地图，或填这张房间地图的编号；
- `force`：**勾上**。会话没变时默认跳过，改了算法之后要重测就必须勾；
- `dry_run`：不勾（勾了只算不上传）。

大约几分钟。完成后后台有新的地图包和一份报告。

### 4. 下载融合后的地图

App「门店数据 → 云端地图」点「刷新云端列表」，有「更新」就点（正常模式会自动装）。「精度测试」清单里「云端融合版本」变绿说明装上了。

### 5. 走测试会话（2～3 段）

「精度测试」页点「开始测试会话」，按页面上的提示：

- 走一条**和建图时不同**的路线，2～5 分钟，正常步速；
- 从一个能准确指出的点出发（地上贴一条胶带或标一个桌角），在地图上长按这个点，设朝向，直走 1.5 m；
- 走完点「结束采集」。会话标记为 test，不会混进磁场图。
- 多走几段更稳：不同路线、不同时间（早上人少、下午人多）各一段。

### 6. 上传并再融合出成绩

测试会话结束会自动上传（没传上可以在「精度测试」页点「上传本机还没上传的会话」）。
再按第 3 步触发一次云端融合（`force` 勾上）。融合时会用建图会话做磁场图，再把测试会话按冷启动回放一遍，和参考轨迹比。

### 7. 看成绩

回到「精度测试」页，下拉到「最新成绩」，点「刷新云端成绩」。页面下半部分是最近 5 次融合的中位误差趋势。

## 怎么读数字

| 指标 | 含义 |
|---|---|
| 中位 | 一半的时刻误差比它小，最主要的数字 |
| P90 | 九成的时刻误差比它小，看「坏的时候有多坏」 |
| ≤1 m | 误差在 1 米内的时刻占比 |
| 首次定位 | 开始走多远才第一次定位成功；「没定到」= 整段都没收敛 |
| 跳 | 位置突然跳走的次数，应当接近 0 |
| 错定 | 自信地定在 5 m 以外的比例，比中位更伤用户体验，要压到 0 附近 |
| 只看建图覆盖到的地方 | 测试里走到建图没走过的地方，磁场图里没数据，必然不准；这一行把那些点去掉，看磁场图本身的水平 |

每个测试会话云端会用不同随机种子跑 3 遍，页面显示的是平均值。

## 好是什么样

先说实话：这些是预期，不是承诺，第一次测出来再校准。

- 参考不是真值。参考轨迹 = 这段测试自己的 ARKit + 起点。起点点偏 30～50 cm、走几分钟后 ARKit 漂 0.5～1 m，都会算进「误差」，所以成绩有 0.5 m 左右的底，低于它的差异分不出来。
- 200 m² 的办公室，地磁起伏比较平，工位、柜子、电脑、钢结构对磁场的影响各处不同，有些地方特征明显，有些地方很平。
- 可以这样期待：
  - 中位 1～2 m：可用；
  - 中位 2～3 m：磁场图还不够密，或这间办公室磁场太平，补采建图会话；
  - 中位 > 3 m 或常「没定到」：先检查建图会话够不够、有没有走满，再看算法；
  - ≤1 m 占比 30～50% 已经不错；
  - 首次定位 5～15 m 的步行距离正常（冷启动要走一段才能收敛）；
  - 跳和错定应当接近 0。
- 同一批测试会话在不同版本之间比才有意义。别在两次融合之间增减测试会话，否则比的不是同一批数据。
- 只有 2、3 段测试会话时，一个会话里的偶然（路线刚好经过磁场平坦处）会让数字抖 20～30%。算法改动带来 10% 以内的变化，别急着下结论，多走几段再看。

## 改算法后怎么重测

1. 改完算法推到仓库，不用重新采集；
2. Actions → Cloud map build → Run workflow，`force` 勾上；
3. 「精度测试」页刷新成绩，看趋势里这一版比上一版是变好还是变差；
4. 测试会话数量要和上一次一样（页面趋势里每个条目会显示「N 段测试」）。

## 常见问题

- **「最新成绩」是空的 / 提示没有测试成绩**：测试会话没传到后台，或传完后没有重新融合。先看清单里「测试会话」是否写着「N 段还没出成绩」。
- **清单说没有融合版本**：还没跑过第 3 步，或这张地图的会话没传到后台（手机要连过一次后台，地图 JSON 才会上传）。
- **中位很好但「错定」不为 0**：部分时刻定到了很远的错地方又拉回，看「首次定位」和「跳」，通常是冷启动阶段，不是稳定后的问题。
- **成绩突然变差**：先确认测试会话批次没变；再看趋势旁边的「建图 N 个会话」，建图会话变了磁场图也会变。
